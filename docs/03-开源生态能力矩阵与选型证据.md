# ADS-OSS-003｜跨开源产品能力矩阵与 PoC 决策

> 研究日期：2026-10-31；2026-11-01 追加 DeepSeek Harness 子代理评估。以下"支持/特点"基于各项目公开仓库和文档，**没有在用户的 OpenCode 及业务环境进行兼容性实测**。
> 采纳动作：**采用协议/工具、先 PoC、只借鉴、暂缓**四种；任何"开源"不等于代码可无条件复制。

## 1. AI 编码、Agent Harness 与可靠执行

| 项目 | 上游 | 已公开的差异化能力 | ADS 初选 | 验证重点 |
|---|---|---|---|---|
| OpenCode | https://docs.opencode.ai/docs/tools/ | 原生 Skill、Agent、Tool、权限和 SDK | 默认主开发宿主 | 子代理真实事件、进程异常、权限拒绝、当前版本 API |
| DeepSeek Harness (DSH) subagent | https://github.com/deepseek-ai/deepseek-harness（packages/subagent） | 基于 Cordis「一切皆插件」；原生 subagent / subagent_fork / workflow / ralph 派发，list_agents / send_message / interrupt_agent 监督；上下文隔离、轨迹可审计、可作外部 agent 代理；MIT | 只借鉴 ralph 交接与上下文隔离模式，不整体接入运行时 | 不引入第二套执行循环；DeepSeek 非 OpenAI provider 下子代理 payload 不可见（codex #36586）；不解除模型额度阻断 |
| didi/helixharness | https://github.com/didi/helixharness | 知识索引、确定性路由、工作区范围、评测演进 | 先 PoC 部分能力 | 不引入重叠 Spec/审批；兼容 OpenCode |
| Open SWE | https://github.com/langchain-ai/open-swe | PR/CI/评论驱动的软件工厂、LangGraph durable thread、沙箱 | PoC 运行可靠性思想 | 托管运行要求、权限、安全、恢复语义 |
| OpenHands SDK | https://github.com/OpenHands/software-agent-sdk | 独立 Agent SDK、临时/远端工作区、事件 API | 可选替代宿主 | 隔离执行与集成成本；不并行维护两个默认宿主 |
| GSD / get-shit-done | https://github.com/gsd-build/get-shit-done/blob/main/docs/ARCHITECTURE.md | 新鲜上下文、波次依赖执行、薄编排、项目状态 | 借鉴 + 小型路由对比 | 是否改善首轮成功率；不得复制其全部指令与状态 |
| Superpowers | https://github.com/obra/superpowers | 调试、TDD、Git worktree、独立子代理评审 | 保留适用 Skills | 不与路由器/规格系统争夺权威 |
| SWE-agent / mini-SWE-agent | https://github.com/SWE-agent/SWE-agent | 代码修复 Agent 与评测可复现基线 | 评测参考 | 统一模型+预算下与 OpenCode 对比 |
| Dagger | https://docs.dagger.io/getting-started/introduction/ | 沙箱化、缓存、可编程流水线、带类型的构建产物 | 按需 PoC | 复用已有 CI 时是否仍有新增价值 |

## 6. 复用与选型准入表（每项必填）

| 维度 | 记录要求 |
|---|---|
| 上游版本 | 仓库、固定 commit/tag、读取日期、稳定性声明 |
| 许可 | LICENSE、NOTICE、传染/网络服务限制、样本与训练数据单独授权 |
| 使用形式 | 理念借鉴 / 通过 CLI 或 API 调用 / 依赖库 / 源代码复制 |
| 宿主兼容 | OpenCode 原生入口、SDK/CLI 版本、退出码/结构化输出实测 |
| 网络与密钥 | 是否联网，如何隔离测试数据及 API 凭据 |
| 核心收益 | 对特定失败反例的改善或减少的自研维护面积 |
| 退出机制 | 移除依赖后能否保持证据原格式和受控失败能力 |

**证据边界：**以上是来自公开来源的静态研究结论，尚未完成用户项目的依赖安装、端到端 PoC 或许可证正式法律审查。未经运行的项不得写“已验证兼容”。
