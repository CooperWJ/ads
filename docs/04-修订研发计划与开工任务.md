# ADS-PLAN-003｜生态复核后的研发路线、PoC 和验收任务

> 状态：设计任务，不是实现报告；基线 ADS-ARCH-003。保留 ADS 三大目标和 M0～M5 框架，但将最容易“再次闭门造车”的自研工作改为上游能力 PoC 后决策。

## 1. 重排的里程碑与放行条件

| 阶段 | 交付焦点 | 不可替代的通过标准 | 不能做的事 |
|---|---|---|---|
| M0a | 评测案例可信度 | Golden PASS / empty FAIL / bad variant FAIL / clean image regrade 一致 | 评分器没有自证就评价 Agent |
| M0b | 开源能力选型 | OpenCode、Playwright Agents、Harbor、GSD/HelixHarness/Open SWE 各有固定版本 PoC 报告 | 未实测就决定新写协调层 |
| M1 | 原始来源与交付义务 | 来源清点、解析边界和独立遗漏均可复现 | 从 SPEC 自证完整 |
| M2 | 可靠 AI 开发 | 真 OpenCode 能完成一条小切片，中断恢复不重复副作用 | 子代理 done 即任务完成 |
| M3 | 真实验收与 QA | UI/API/DB/QA 独立执行，有受保护预期 | healer 删除断言换 PASS |
| M4 | 受信 CI 与部署 | 干净环境独立评分、构建身份、部署冒烟 | 本地 PASS 伪装受信交付 |
| M5 | 三轴对照与迁移 | 原始需求/可靠开发/交付效果以及成本可对照 | 只展示新版本好看的案例 |

## 2. 第一批立即执行的 M0a/M0b 任务

| ID | 任务 | 依赖 | 实际交付与反例 |
|---|---|---|---|
| A00 | 整理历史实际问题（只读） | 无 | 10087 和后续 bug 分类为“漏需求/占位接口/UI/QA/证据”；不将用户业务代码放进模板 |
| A01 | 建立完全虚构的 UI→API→DB→保存→导出参考工程和原始线框图 | 无 | Golden Path 用真实浏览器和数据库通过，来源与程序故意分离创建 |
| A02 | 定义单个评测任务的 `base/ref/empty/bad` 四类状态 | A01 | 正确参考 PASS，空补丁 FAIL，缺字段等坏变异 FAIL，同等正确实现不误判 |
| A03 | 冻结评分器与干净镜像重评 | A02 | Agent 修改本地测试或缓存后，独立评测仍 FAIL；评分器不可被 Agent 读取或修改 |
| A04 | Harbor 自定义任务 + Agent Adapter PoC | A02,A03 | 实际通过 Harbor 跑一项参考任务和一个坏案例；记录版本、命令、结果、资源、障碍 |
| A05 | Playwright Test Agents + OpenCode PoC | A01 | `planner/generator/healer` 真实执行；缺必需字段/Mock 替换/删除断言不能骗过外部测试 |
| A06 | OpenCode 原生执行能力核对 | A01 | Session、Subagent、权限、退出码、中断恢复、隔离工作区、读写范围有日志与版本 |
| A07 | GSD、HelixHarness、Open SWE 可靠性对照 | A06 | 同样的输入/预算/模型（可行范围），测量恢复、上下文漂移、工具故障及自主修复 |
| A08 | 发布开源复用 ADR | A04~A07 | 每项明确 `REUSE/ADAPT/LEARN/REJECT`、许可证/维护/退出；删除已被上游满足的自研任务 |

A02/A03 是硬性前置。**如果评分题目没有区分能力，后续任何 agent/harness 对照成绩无效。** 如果 Harbor 无法适配 OpenCode，也不意味着要立即自己写整套框架：先隔离 CLI Adapter，再记录失败范围。

## 6. 强制停止、回滚与验收的最少机制

- 不新增第二套规格权威、QA 状态机、浏览器测试生成器、Agent Loop、测试/评测执行平台或自签名信任服务。
- 每增加一个 Adapter，明确原有哪项自研任务不再做。任何工具引入不得使 OpenCode 原生生产路径失效。
- 评分系统不能看到/修改候选工作区之外的结果；若发现评测数据泄漏，撤销该评测批次，不把得分计入版本提升。
- QA 独立用例必须可使用原始多 Sheet，不强制人工 requirementID；QA 与 DEV 的验收和身份不可互相替代。
- 本轮文档为研究修订版，不等于发布。任何软件发布继续按递增新版本、CHANGELOG、完整 ZIP、Diff、统计、实测结果和哈希交付。

## 7. 推荐第一次 PoC 的明确切片

运行对象是**虚构的项目清单管理系统**：存在页面列表、详情、七个只读属性、动态查询、保存、导出 XLSX 和权限示例，不写入任何实际业务规则。先用 Playwright 真浏览器跑通 `查询→加载→编辑→保存→刷新→导出`，再分别制造 `缺整个字段 / API 200 占位 / UI 运行异常 / 导出内容缺列 / QA PENDING / 旧 PASS 复用 / 会话中断 / 检查器自改`。每个缺陷均应保留坏版本、执行日志、失败截图/Trace 与正常修复后的运行证据。
