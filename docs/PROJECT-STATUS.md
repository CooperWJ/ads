## 当前迭代

本轮在真实模型额度可用后重试 `ads develop --execute`，突破了此前持续标注的 MODEL_QUOTA 阻断：`opencode/deepseek-v4.1-flash-free` 在虚构开发切片上真实执行（原生 Session `ses_e6a5c0bc…`，第二次 `--session` 续接身份 CONFIRMED），修改 `app.py`、`web/index.html`、`web/app.js` 三个交付文件并新增 `dev_tests/test_user_journey.py` 集成自测，7 项自测全部通过（导航/七字段持久化/加载失败/越权写拒绝/保存持久化/XLSX 导出/非法载荷）。须如实记录：失败定位中发现一处自测预期错误（"匿名写"经 `save()` 默认 editor 角色发请求，未能触发服务端 403），由人工修正后才全绿——即**应用权限逻辑本身正确，是测试预期 bug**。本轮未做容器外独立验收，`ads develop` 仍如实标为 `EXECUTED_UNVERIFIED`，不构成完整交付、QA 或独立验证。

v0.6.17 增加只读本地交付就绪汇总：开发义务和 QA 用例必须在同一完整项目快照上各自执行通过，开发运行必须绑定 OpenCode Session；缺失 QA、快照漂移或任一未验证项均阻断。加载运行记录时重新核对配置检查集合、进程退出、失败分类、用例结果及报告/日志路径。READY 只代表本地证据齐备，仍不授予独立 QA、语义完备或发布授权。

v0.6.16 将 QA 每条已确认用例与原始 Sheet/行、用例哈希、预期、外部审查引用和本次执行结果绑定；唯一测试匹配引用 run、输入快照及原始报告哈希，缺失/重复映射阻断。该结果仍为本地执行观察，不签署独立 QA 身份或 QA_ACCEPTED。

v0.6.15 将每项已确认义务的预期结果与本次实际用例结果并列输出，引用验证 run、输入快照、检查/用例 ID 和原始报告哈希；缺失或重复用例证据不通过。它提升了结果可追溯性，不证明义务语义正确、需求绝对完备或 QA 独立性。

v0.6.14 将低敏行为摘要带入 `ads verify` 回执，使开发运行、变更清单、行为观察与验证结果在同一记录中可见；摘要由开发证据哈希绑定，不复制原始命令、提示词或工具输出。

v0.6.14 增加可识别测试命令进程退出结果统计（exit_zero/nonzero/unknown），未知退出码不计为成功；仅是进程事实，不代表测试断言质量。v0.6.13 增加最后一次直接编辑后的验证观察：记录最后可识别测试命令与最后直接编辑的顺序及退出结果；缺少最终 stop 事件或测试/编辑证据时保持 INDETERMINATE。它不等同于需求符合性证明。

v0.6.12 为每次原生开发运行生成实际文件变更清单（新增/修改/删除），来源于执行前后 Git 快照，覆盖跟踪及未忽略文件；忽略文件不在清单内，不可读取时显式 UNKNOWN。它为后续与任务范围、需求义务的对照提供事实，不自行判断改动是否合理。

v0.6.11 对显式原生 Session 续接增加身份核对：仅当 OpenCode JSONL 中观察到请求的 sessionID 才确认；错配或缺失身份会阻断续接声明。它不等于副作用恰好一次或完整恢复协议已验证。

v0.6.10 为原生 OpenCode error event 增加低敏分类：提取安全格式的状态码、错误代码和 Provider ID，区分模型额度、限流、权限、超时及上游故障，不写入原始错误消息，不自动重试或切换模型。确定性合成事件覆盖分类规则；这不是新的模型请求或额度已恢复的证明。

v0.6.9 将 OpenCode 单次开发记录与后续 `ads verify` 结果建立精确关联：开发运行写入唯一 ID、输出快照及行为摘要哈希；验证记录引用对应运行，并在加载时重新核对摘要/行为文件。开发后代码变化标记 STALE，证据篡改阻断旧验证记录。该机制只解决证据错配，不证明 Agent 遵循了技能，也不替代业务断言和独立 QA。

当前接入固定版本 e2e 的原生 report-1 与真实产品旅程，复用同一 `ads verify`。运行 41262125347 已完成真实保存/刷新/SQLite/XLSX 下载，假保存与缺导出列均失败；OpenCode 2.2.3 已实际连接 MCP 并显式激活 e2e 技能。模型开发新尝试仍返回 provider.free-limit，0 工具调用、0 候选变更；不替换账户或冒充模型完成。见 [e2e 接入说明](E2E-JOURNEY.md)。

补齐明确的原生 Session 续接参数和异常收尾摘要；中断、启动失败、执行后上下文不可读不再丢失执行记录。QA 可以先导入用例并检查质量，需求对照缺少输入时独立报告阻断。上述能力不代表模型恢复、远程副作用幂等或正式 QA 验收已经证明。

新项目已可从原始材料加载上下文并调用原生 OpenCode，不必先准备验收契约、规格目录和映射表。初始化提供可编辑任务入口；缺少确认要求时只支持探索与开发执行，不能认可正式验收。相关材料后续新增仍使旧上下文失效。

本轮修复 `ads develop --execute` 的进程函数同名遮蔽阻断，增加实际子进程的成功、非零退出、超时和预览回归。该验证只覆盖原生调用适配；未消除模型额度阻断，也未完成 OpenCode 真实开发切片。

当前提供可安装项目 CLI、来源差集、OpenSpec 只读派生、标准测试器和 QA/出处适配。171 项测试和四条 PR CI 已通过；主分支标准出处已验证，见 docs/evidence/core-v0.6.0-validation.json。完整任务逐项状态见 [能力矩阵](IMPLEMENTATION-MATRIX.md)。代码、合成测试、实际集成与最终授权分别验收。

## 后续按可交付结果推进

1. 首要成果是完整开发切片：从一份原始需求到可运行、可操作的功能，由 OpenCode 实际完成实现和调试，独立测试运行 UI/API/DB 旅程。先利用已接入的原生与开源能力，记录需求遗漏、失败、人工介入和成本。模型条件不足时如实阻断，不转而堆积门禁。
2. 围绕同一切片补齐独立 QA：从原始多 Sheet 用例核对预期并实际执行；不强制人工 requirementID。优先接入现有测试工具；仅在真实集成暴露缺口时增加适配。开发测试生成与独立验收保持各自预期。
3. 受保护执行与发布条件按使用场景补齐：沿用 Harbor 和现有 CI，管理员权限不足不妨碍可独立开展的本地开发与集成，也不将局部通过声称为受信发布。暂停与当前切片无关的通用门禁和审批扩展。
4. 第二项目试点：Python/Node 双仓虚构项目已通过配置接入，继续需要新鲜项目和原始材料检验泛化效果，不把项目语义写入核心。
5. 小规模同条件对照：原生 OpenCode、冻结旧脚手架、ADS；报告遗漏、首次可用、人工介入、成本和时延。小样本只给探索性结论。

每轮只发布已实际完成的范围。完整产品收益尚未验证，不以版本数、脚本数和测试数替代效果。

开源复用直接服务当前问题：优先使用现成能力，做最小必要配置或薄适配，不为接入而同时叠加多套框架。实现替代后删除重复逻辑。新增技术选型只需足以判断能否解决当前问题，不另建审批流程。
