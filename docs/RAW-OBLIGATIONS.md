# 原始需求完整性验收原型（M0→M1 桥梁）

## 为什么做

过去脚手架可能出现“已有测试全通过，却漏掉需求中整个按钮或字段”的情况。本版不从代码覆盖结果推导需求完整，而是由**评测方**单独审视原始资料、建立验收义务，再将义务关联到真实检查。已实现范围严格限定为虚构示例的结构化 Markdown 与 SVG 文本节点。

## 已实现

- `brief.md` 的单一业务要求段落包含 6 句；每句需要在 `brief_sentences` 里出现，绑定至少一个真实义务。对格式漂移采用 fail-closed，需要重新人工审核 source parser；避免静默忽略新需求。
- SVG 中的 13 个 `<text>` 元素全部需要映射到独立义务；增加或移除任何一项都会触发缺口。页面标题、选择控件、7 个只读字段、编辑备注和保存/导出均在清单中。
- 每项义务有来源原文定位、必需检查引用、浏览器必测标识。可见 UI 均不能通过把 `browser_required` 改为 false 逃避浏览器真实验收。
- 执行层采用现有 HTTP、SQLite、XLSX、Node 和 Playwright。交付层强制附加独立 QA 和源码绑定证据；缺失执行返回 `NOT_VERIFIED`，错误返回 `FAIL`。
- `--require-delivery` 与旧 `--profile` 区分：低级 Profile PASS 是阶段性进展，不等于可交付。

## 明确尚未实现

1. 通用文档结构、表格、截图、录屏自动解析及枚举完整性，和跨来源的语义一致性；这些属于 M1。
2. 非结构化语义遗漏的自动完备证明。目前 6 句是固定格式的 fixture-specific 句子拆分，必须有独立人工/QA 复核。
3. 真正的隐藏验收服务器、执行容器、OpenCode/Harbor 实际连接和可信外部 CI；目前本地评测器源码和 rubric 都在同一个分发包中。
4. 真实浏览器的成功截图和 Trace。本环境没有 Playwright 对应浏览器二进制，系统浏览器策略亦有限制。

## 新增反例

删除整项导出、删七个字段中的任一项、从 rubric 删除查看者禁止修改、增加未登记的 SVG/brief 内容、伪造检查引用、浏览器未运行却宣称交付、独立 QA 未通过、证据哈希不一致，均需要阻断/拒绝或 `NOT_VERIFIED`。
